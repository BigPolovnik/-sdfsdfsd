Дата: 15.10.2026

## Импорт каталога

- `backend/MoviePlatform.Application/VibixCatalogService.cs`
  - Добавлен `GetVideosPageAsync`: запрашивает ровно одну страницу `/api/v1/publisher/videos/links?page=N&limit=50&is_uploaded=true`.
  - Оставлена обработка повторных запросов при HTTP 429 и задержки между страницами.
  - `iframe_url` из каталога сохраняется в существующее поле `PlayerUrl`; URL принимается только по HTTPS.
  - Детальный запрос `/publisher/videos/kp/{kpId}` распознаёт как `iframe_video_id` (старый формат), так и `id` из актуальной OpenAPI-схемы.
  - Поля `year`, `kp_rating`, `imdb_rating` теперь разбираются и при числовом, и при строковом JSON-представлении.

- `backend/MoviePlatform.Application/VibixSyncService.cs`
  - `SyncAsync` больше не загружает весь каталог в память перед сохранением.
  - Каждая страница обрабатывается и сохраняется в PostgreSQL отдельно.
  - Если последующий запрос завершается ошибкой или ограничением частоты, ранее сохранённые страницы остаются в базе.
  - Добавлены логи по каждой сохранённой странице и общей статистике.

- `docker-compose.yml`, `.env.example`
  - Размер страницы по умолчанию изменён на 50 записей. Значение ограничивается кодом сервиса сверху до 50.

## Что показывает приложенная документация Vibix 1.1.0

1. Список загруженных видео: `GET /api/v1/publisher/videos/links`; параметры `page` и `limit`, ответ с массивом `data`.
2. Подробности по Kinopoisk ID: `GET /api/v1/publisher/videos/kp/{kpId}`. Пример ответа содержит `id`, `iframe_url`, `embed_code`, рейтинги и метаданные.
3. В документации список видео использует `poster_url`, `backdrop_url`, `name_rus`, `name_eng`, `voiceovers` и другие поля. Часть старых интеграций использует иные имена (`preview`, `embed_code_new`, `iframe_video_id`), поэтому нельзя смешивать эти контракты без совместимости.
4. Примеры схемы представляют `year` и рейтинги числами. DTO теперь принимает эти поля как JSON-скаляры.
5. API-страница документирует максимум 100 Kinopoisk/IMDb ID для соответствующих фильтров; это не ограничение общего каталога. Для импорта используются небольшие страницы по 50 записей.
6. PDF и HTML в архиве соответствуют одной документации Swagger/OpenAPI 1.1.0; HTML-папка `!Vibix API Documentation_files` содержит ресурсы оформления страницы, а не отдельный контракт API.

## Проверка и ограничения

- Исходники C# и frontend изменены. В этой среде отсутствует .NET SDK и Docker Engine, а `node_modules` не приложен, поэтому полноценную сборку контейнеров здесь запустить нельзя.
- После распаковки на Windows выполните `docker compose up -d --build api frontend`, затем `docker compose logs -f api`.
- Синхронизацию с реальным токеном Vibix нужно проверить в твоём Docker: внешние ответы API не проверялись из этой среды.
- Архив не содержит `.env`, чтобы не пересылать секреты. Сохрани свой существующий `.env` при обновлении проекта; не публикуй токен Vibix или `ADMIN_KEY`.
